# Habit Pulse 実装要件

## 初版の実装状況（2026-11-19）

以下は設計時の要件を保存した文書です。
初版では登録・編集・今日の実施/取消・アーカイブ・履歴・7日間の達成率を実装しました。
実施操作はカードから詳細画面を開いて行います。
履歴の絞り込みはAPEX標準レポート機能を使用します。
現役/アーカイブの専用切り替え、連続達成日数、ヒートマップ、保存した選択色のカードへの反映は、初版では実装していません。
別ユーザーの更新拒否はAPI層で検証し、別ブラウザーでのユーザー間参照確認は実施していません。
確定した実装範囲と実測結果はarticle.mdおよびimplementation-notes.mdを参照してください。

## 目的と範囲

毎日取り組む習慣を登録し、その日の実施を記録するOracle APEXアプリをAPEXlangで実装する。
保存先はADBとし、画面操作と保存・集計が一致することを実機で確認する。
初版は毎日実施する習慣のみを扱い、曜日別頻度、通知、SNS共有、外部API連携は含めない。

## データモデル

アプリ固有の永続テーブルは次の2表とする。
IDはデータベースで生成する。

### HT_HABIT：習慣

| 列 | 要件 |
|---|---|
| HABIT_ID | 数値の主キー |
| OWNER_NAME | APEXの認証済みAPP_USERを保存する必須列 |
| HABIT_NAME | 習慣名、1〜80文字、空白のみは禁止 |
| DESCRIPTION | 説明、最大500文字、任意 |
| COLOR_CODE | 許可済みパレットから選ぶ表示色 |
| ICON_NAME | 許可済みアイコン名 |
| START_DATE | 開始日、JSTの暦日 |
| ARCHIVED_DATE | アーカイブ開始日、JSTの暦日、現役時はNULL |
| DISPLAY_ORDER | 表示順 |
| CREATED_AT | 作成日時 |
| UPDATED_AT | 更新日時 |

### HT_CHECKIN：実施記録

| 列 | 要件 |
|---|---|
| CHECKIN_ID | 数値の主キー |
| HABIT_ID | HT_HABITへの必須外部キー |
| CHECKIN_DATE | 実施日、JSTの暦日、時刻部分なし |
| NOTE | メモ、最大500文字、任意 |
| CREATED_AT | 作成日時 |

`(HABIT_ID, CHECKIN_DATE)`に一意制約を付け、同じ習慣・同じ日への二重登録をデータベースでも防ぐ。
CHECKIN_DATEには時刻部分を保存しない制約または正規化を適用する。
HT_CHECKINの所有者は親のHT_HABITから導出し、不整合な重複所有者列を持たない。

## 利用者ごとの分離

認証はAPEXの既存アカウント方式を使用する。
すべての一覧・集計・詳細取得・更新・チェック操作で、親習慣のOWNER_NAMEが認証済みAPP_USERと一致することを検証する。
OWNER_NAMEをブラウザーの入力値から受け取らない。
ログイン時の利用者識別子を採用し、大文字小文字の扱いは作成・参照・更新ですべて統一する。
別利用者のHABIT_IDやCHECKIN_IDを指定しても、参照・更新・削除できないことを確認する。
HTMLに表示する習慣名・説明・メモは必ずエスケープする。
書き込みはAPEXの認証済みセッションとセッション保護下で実行する。

## 日付と実施記録

「今日」はデータベースサーバーやブラウザーのタイムゾーンによらず、日本標準時（Asia/Tokyo）の日付とする。
SQLでは`TRUNC(CAST(SYSTIMESTAMP AT TIME ZONE 'Asia/Tokyo' AS DATE))`に相当する共通の定義を使用する。
初版で記録・取り消しできるのは今日の現役習慣のみとする。
未来日への記録はできない。
二重クリックやリクエスト再送でも記録が増殖しない実装とする。
取り消し済みの記録への再度の取り消しも安全に処理する。
メモ更新時も親習慣の所有者を検証する。

## アーカイブ運用

習慣の削除ボタンは設けず、アーカイブ操作を用意する。
アーカイブしても既存の実施記録を保持する。
アーカイブ済みの習慣は「今日」の対象から外し、履歴では参照できる。
アーカイブ開始日以降は達成率の分母から外す。
初版ではアーカイブの解除は実装しない。
履歴の対象日判定は`START_DATE <= 対象日`かつ`ARCHIVED_DATE IS NULL OR 対象日 < ARCHIVED_DATE`とする。
アーカイブ日に既存の今日の実施記録がある場合、記録は履歴に残すが、その日以降の予定・達成率からは除外する。
この挙動を画面の短い補足で説明する。

## 画面

### 今日

日付、現役習慣数、今日の達成数、達成率を表示する。
習慣をカードで表示し、実施済みの切り替えを行う。
データ0件では習慣追加への導線を表示する。
チェック後はカード、達成数、達成率が同じ保存状態を表すよう更新する。

### ダッシュボード

過去7日間の達成率の推移と習慣別の達成状況を表示する。
集計の期間はJSTの今日を含む直近7暦日とする。
分母は各日の対象習慣数、分子はその対象習慣に対する実施数とする。
分母0は0%と断定せず「対象なし」と表示する。
割合にはパーセント記号、グラフには軸名・期間・系列名を付ける。
参考用の過去データは明示的なデモデータ投入手順だけで追加し、通常の利用者へ自動投入しない。

連続達成日数を表示する場合、習慣ごとに計算する。
今日が実施済みなら今日を起点、今日が未実施なら昨日を起点として、連続した実施日数を数える。
開始日前へ遡らない。
画面でこの定義が分かる短い説明を付ける。

### 習慣管理

習慣の追加、名称・説明・色・アイコン・表示順の編集、アーカイブを行う。
開始日は登録時のJSTの今日とし、通常UIから変更させない。
現役とアーカイブ済みを切り替えて表示する。
バリデーションエラーは対象項目の近くに表示する。

### 履歴

日付、習慣名、メモを表示する。
日付範囲と習慣で絞り込めるようにする。
アーカイブ済みの習慣の記録も含める。
履歴から過去日の達成状態を変更する機能は初版に含めない。

## UI

白と深緑を基調とするミニマルなデザインを採用する。
広めの余白と読みやすい文字を用い、今日の操作を最優先に配置する。
色だけに依存せず、実施済みは文字とアイコンでも区別する。
デスクトップとスマートフォン幅に対応し、キーボードでも主要操作ができるようにする。
画面の実装説明や内部SQLを通常の利用者の画面に載せない。

## 受入確認

1. 習慣を追加し、再読み込みしても保持される。
2. 今日の記録と取り消しが保存・画面・集計すべてに反映される。
3. 同日の重複記録が一意制約で防止される。
4. 別利用者の一覧・集計・更新経路からデータへアクセスできない。
5. JSTの日付を使用している。
6. 空データ、記録0件、分母0で画面が破綻しない。
7. アーカイブ後も履歴が保持され、今日の対象から外れる。
8. グラフの値がSQL集計結果と一致する。
9. 実機のPC画面とスマートフォン幅のスクリーンショットを取得する。
10. APEXlang検証とインポートの結果・使用バージョンを証跡として保存する。
