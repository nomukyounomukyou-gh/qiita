# 東都マート 店舗POS障害 初動対応手順書

文書ID: RB-POS-01  
版: 1.2  
適用開始日: 2026-10-01  
管理部門: 店舗システム運用  
対象: `POS-CORE-DB` および各店舗の `STORE-xxx-POS`

> この手順書、システム台帳、監視アラートはハッカソン用に作成した架空の資料です。連絡先もデモ用です。

## 1. 目的と判断の前提

監視アラートを受けた担当者が、影響範囲と初動の確認項目をそろえ、適切な担当へ連絡するための手順です。監視の発報レベル（`critical` / `warning`）と、業務上の対応優先度（P1 / P2 / P3）は別の項目です。

アラートの「影響店舗数」は監視上で異常を観測した店舗数です。販売が停止した店舗数と断定しないでください。優先度は暫定とし、店舗からの確認結果で更新します。

## 2. 対応優先度の基準

判定には、同じアラートの `duration_minutes` と `affected_store_count_observed` を使用します。対象が台帳に存在しない場合、または必要な値が欠ける場合、優先度を推定せず「未判定」とします。

| 優先度 | 判定条件 | 初動の目安 |
| --- | --- | --- |
| P1候補 | POS共通基盤の障害で、異常を観測した店舗が10以上、かつ継続時間が15分以上 | 直ちに店舗システム運用とインシデント責任者へ連絡。業務影響を確認 |
| P2候補 | P1に当たらず、POS共通基盤の障害が15分以上継続、または2～9店舗で異常を観測、または単一店舗のPOS障害が10分以上継続 | 店舗システム運用へ連絡し、影響拡大を監視 |
| P3候補 | 台帳登録済みの単一店舗POS端末の障害で、継続時間が10分未満 | 店舗システム運用で状況を確認。必要なら店舗へ連絡 |
| 未判定 | 台帳に対象がない、対象区分が不明、または判定に必要な値が欠ける | 台帳管理者に対象IDを確認し、優先度判定を保留 |

複数の条件に該当する場合は高い優先度を採用します。対象がPOS以外の場合は、そのシステムに対応する手順書を確認してください。この文書だけでPOS以外の優先度を決めないでください。

## 3. 初動手順

1. アラートID、システムID、発生時刻、継続時間、観測された店舗数を記録する。
2. システム台帳で対象ID、担当部署、連絡先、適用する手順書IDを確認する。該当がなければ「未判定」とし、台帳管理者（店舗システム運用）へ照会する。
3. 直近15分の監視画面で同じ症状が続いているか、復旧済みかを確認する。複数店舗のアラートなら、影響店舗一覧に重複がないか確認する。
4. 店舗側または運用担当に、決済・会計処理が実際に停止しているか確認する。監視の接続失敗だけで販売停止と断定しない。
5. 第2章に沿って暫定優先度を付け、根拠となるアラート値と該当条項を対応票に記載する。
6. P1候補は台帳の `primary_contact` と `escalation_contact` の両方へ連絡する。P2/P3候補は `primary_contact` へ連絡し、影響拡大・長期化時にエスカレーションする。

## 4. 対応票に残す項目

- アラートID、観測時刻、対象システムIDと台帳上の名称
- 観測された影響店舗数と、実際の販売影響の確認状況
- 暫定優先度と判定条件。未判定なら不足情報
- 実施済みの確認、次に確認すべき事項、担当部署と連絡先
- 参照した台帳レコードと本手順書の文書ID・節番号

## 5. 作業上の制限

この初動手順では、DB再起動、端末再起動、通信設定変更などの復旧操作を指示・自動実行しません。復旧操作は担当者が別の承認済み手順に従って判断します。Agentが作る対応票は下書きであり、連絡や起票の実行前に担当者が内容を確認します。
